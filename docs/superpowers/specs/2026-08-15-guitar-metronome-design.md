# 吉他练习节拍器设计规格

- 日期：2026-08-15
- 状态：待用户书面复核
- 已选 UI：A「琴弦脉冲」
- 目标部署：GitHub Pages（GitHub Actions 自动部署）
- 产品定位：手机竖屏优先，完整适配桌面端

## 1. 背景与目标

在空 Git 仓库中构建一个无需后端的吉他练习节拍器。产品应当不仅能稳定播放节拍，还要覆盖成熟节拍器中对日常器乐练习最有价值的功能：拍号和细分、逐拍强弱编辑、自动递增/递减速度、循环训练、静音小节训练、计时以及本地练习预设。

核心目标：

1. 在浏览器前台运行时，以 Web Audio 音频时钟为准稳定排程，避免使用 UI 定时器直接发声。
2. 手机放在谱架上时，使用者能从较远距离辨认当前拍、强拍和训练进度。
3. 常用控制可以在主界面完成，高级参数收纳在底部抽屉中。
4. 全部用户数据保存在浏览器本地，不依赖账号或服务器。
5. 每次默认分支更新通过自动检查后部署到 GitHub Pages。

## 2. 非目标

V1 不包含：

- 吉他调音器；
- 复节奏（Polyrhythm）；
- 完整鼓机或伴奏曲库；
- MIDI 输入输出；
- 麦克风识别弹奏准确度；
- 账号、服务器数据库和跨设备云同步；
- 歌曲音频、在线曲谱或第三方音乐服务集成；
- 后台或锁屏状态下持续播放的保证。

隐藏页面或浏览器进入后台时，不承诺计时器精度。V1 将安全暂停播放，并在回到前台后明确提示继续，避免产生不可预测的节拍抖动。

## 3. 主界面设计：A「琴弦脉冲」

### 3.1 视觉原则

- 六条细横线构成克制的“琴弦”背景，不使用写实吉他图片。
- 节拍节点置于琴弦之上，当前节点通过尺寸、填充色和数字同时变化。
- BPM 是页面最大的数字，但当前拍的动态变化必须比装饰更醒目。
- 浅色主题为默认主题；同时提供深色主题并遵循系统设置。
- 强弱关系不能只通过颜色表达，还要使用节点粗细、大小和文字/符号。
- 尊重 `prefers-reduced-motion`，关闭不必要的位移动画，只保留即时状态变化。

### 3.2 手机布局

从上到下：

1. 顶栏：产品名称、练习时长、设置入口；
2. 琴弦节拍区：当前小节的全部主拍节点；
3. BPM 区：大号 BPM、速度术语、滑块；
4. 快捷参数行：拍号、细分、训练状态；
5. 主操作区：固定的大尺寸播放/暂停按钮；
6. 底部抽屉：重音、声音、训练、计时、预设等高级设置。

主界面不同时展示所有高级表单。点击“拍号”“细分”或“训练”时，底部抽屉直接打开相应分区。

### 3.3 桌面布局

桌面端保留相同的信息优先级，但将底部抽屉变为右侧设置栏：

- 左侧：琴弦节拍区、BPM 和主操作；
- 右侧：拍号、强弱拍、训练和预设；
- 主节拍区保持在第一视觉焦点，设置栏不超过可用宽度的约 38%。

### 3.4 专注模式

专注模式吸收 C「舞台节拍」的远距离可视性：

- 隐藏所有非必要设置；
- 放大 BPM、当前拍和小节进度；
- 使用四个或更多纵向节拍块显示当前拍；
- 保留播放/暂停、退出和紧急音量控制；
- 训练模式下显示当前阶段、目标 BPM 和循环次数。

## 4. 标准节拍器功能

### 4.1 BPM

- 有效范围：20–400 BPM；
- 调整方式：滑块、直接数字输入、±1、±5、Tap Tempo；
- Tap Tempo 使用最近若干次有效点击的间隔计算，并过滤超时点击和明显异常间隔；
- 播放中修改 BPM 时，在尽可能短且不产生叠音的边界应用新速度；
- 显示常见速度术语只作为辅助，不参与逻辑判断。

### 4.2 拍号

快捷拍号：

- 2/4、3/4、4/4、5/4；
- 6/8、7/8、9/8、12/8。

自定义拍号：

- 分子：1–16；
- 分母：2、4、8、16。

改变分子后，重音数组按照新拍数调整：保留仍然存在的拍，新增拍使用弱拍。用户可一键恢复该拍号的推荐重音。

### 4.3 细分

V1 支持：

- 四分；
- 八分；
- 三连音；
- 十六分；
- Swing/Shuffle。

主拍节点始终代表拍号中的主拍；细分通过节点间的小标记或琴弦脉冲表现，避免把主拍和细分混淆。

### 4.4 逐拍重音

每个主拍按以下状态循环：

1. 强拍（strong）；
2. 次强拍（medium）；
3. 弱拍（weak）；
4. 静音（mute）。

推荐默认值：

- 4/4：强、弱、次强、弱；
- 3/4：强、弱、弱；
- 6/8：强、弱、弱、次强、弱、弱；
- 其他拍号：第一拍为强拍，其余默认弱拍，之后由用户编辑。

细分音使用统一音量设置。V1 不提供每个十六分位置的独立步进编辑器。

## 5. 声音设计

默认声音为常见的高低音经典 Click，并提供：

- 经典 Click；
- 木块/木鱼；
- 鼓棒敲击。

实现原则：

- 不依赖外链音频；
- 优先在启动时生成短 AudioBuffer，或使用仓库内经过许可确认的极短采样；
- 强拍、次强拍和弱拍使用不同的音高、增益和音色包络；
- 提供总音量和试听按钮；
- 切换音色时不得重建整套应用状态；
- 停止、暂停或切换程序时，取消尚未发声的排程节点，避免残留点击声。

## 6. 音频调度架构

### 6.1 时间源

`AudioContext.currentTime` 是唯一音频时间源。React 状态、`setInterval` 和 `requestAnimationFrame` 均不能决定点击声何时开始。

### 6.2 Look-ahead 调度

建议初始参数：

- 调度检查间隔约 25 ms；
- 向前排程窗口约 100 ms；
- 参数作为引擎常量集中管理，经过真实设备测试后允许调整。

Worker 或轻量调度循环只负责唤醒；每个声音的实际开始时间由 Web Audio 节点的 `start(when)` 指定。

### 6.3 视觉同步

音频引擎维护已排程拍点队列。UI 使用 `requestAnimationFrame` 对照 `AudioContext.currentTime` 更新当前拍，而不是另建一套拍子计时器。

视觉状态允许受到屏幕刷新率限制，音频不能等待视觉更新。

### 6.4 生命周期

- 第一次播放必须来自明确的用户手势，以创建或恢复 AudioContext；
- 暂停时取消未来节点并保存逻辑位置；
- 停止时回到第一拍并重置当前小节；
- 页面隐藏时安全暂停；
- 音频设备或 AudioContext 被系统挂起后，界面显示恢复提示；
- 快速连续点击播放按钮必须具备幂等保护，不能创建多个并行调度器。

## 7. BPM 训练器

### 7.1 参数

- 起始 BPM；
- 目标 BPM；
- 每次变化量：1–20 BPM；
- 每个阶段持续时间：每 N 小节或每 N 秒；
- 起始方向：递增或递减；
- 目标行为：停止、保持、回到起点、反向；
- 循环次数：1–99 或无限。

当起始值、目标值和方向冲突时，表单直接提示并阻止开始，而不是静默修正。

### 7.2 状态

训练器状态：

- idle；
- countIn；
- runningStage；
- transitioning；
- holdingTarget；
- completed；
- paused。

状态转换由完成的小节数或音频时间驱动，不由 React 渲染次数驱动。

### 7.3 进度显示

主界面显示：

- 当前 BPM；
- 目标 BPM；
- 当前阶段/总阶段；
- 当前循环/总循环；
- 下一次变化前剩余小节。

如果最后一步不能整除到目标值，最后一次变化直接钳制到目标 BPM，不允许越过目标后再回退。

## 8. Quiet Count 训练

参数：

- 有声小节数；
- 静音小节数；
- 固定或范围内随机静音；
- 静音期间是否保留视觉提示；
- 循环次数或无限循环。

默认设置：声音和视觉同时隐藏。切换阶段必须发生在小节边界。

随机模式使用每轮预先确定的静音长度，确保暂停后恢复不会重新随机并改变当前训练过程。

## 9. 计时、倒数与循环

- Count-in：关闭、1、2、4 小节；
- 结束条件：不限时、指定分钟、指定小节；
- 训练程序结束前一个小节显示提示；
- 完成时使用独立且克制的提示音；
- 暂停期间不消耗训练时间或小节数；
- 用户手动调整 BPM 时，如果训练器正在运行，必须明确选择“更新当前阶段”或“退出训练”，不能产生隐式状态分叉。

## 10. 预设和本地存储

### 10.1 预设类型

- 普通节拍器预设；
- BPM 训练预设；
- Quiet Count 预设。

每个预设包含名称、创建时间、更新时间和版本化配置。

### 10.2 存储

- 使用 localStorage 保存设置和预设；
- 使用带 schemaVersion 的 JSON 结构；
- 提供版本迁移函数；
- 读取损坏数据时保留原始值用于诊断，界面回退到安全默认值；
- 提供 JSON 导入和导出；
- 导入时先校验，不能直接信任文件内容。

V1 不提供账号同步。卸载浏览器、清除站点数据或更换设备会丢失本地预设，界面需要明确说明。

## 11. 建议数据模型

```ts
export type BeatAccent = 'strong' | 'medium' | 'weak' | 'mute';
export type Subdivision = 'quarter' | 'eighth' | 'triplet' | 'sixteenth' | 'swing';

export interface Meter {
  numerator: number;
  denominator: 2 | 4 | 8 | 16;
  accents: BeatAccent[];
}

export interface MetronomeSettings {
  bpm: number;
  meter: Meter;
  subdivision: Subdivision;
  sound: 'classic' | 'woodblock' | 'sticks';
  volume: number;
  countInBars: 0 | 1 | 2 | 4;
}

export interface TempoProgram {
  startBpm: number;
  targetBpm: number;
  stepBpm: number;
  changeEvery: { unit: 'bars' | 'seconds'; value: number };
  targetBehavior: 'stop' | 'hold' | 'restart' | 'reverse';
  repetitions: number | 'infinite';
}
```

最终字段可在实施计划中细化，但业务含义不得依赖 UI 组件内部状态。

## 12. 状态和模块边界

建议模块：

- `audio`：音频上下文、音色缓冲、未来节点排程；
- `rhythm`：拍号、细分、重音序列和拍点数学；
- `training`：BPM 与 Quiet Count 状态机；
- `storage`：预设、校验和迁移；
- `ui`：React 组件、表单和视觉同步；
- `app`：组合当前设置、播放状态和训练会话。

音频引擎保持为普通 TypeScript 类，不直接依赖 React。React 通过明确命令控制引擎，并订阅只读运行时快照。

## 13. 响应式与可访问性

- 支持至少 360 px 宽手机界面且无横向滚动；
- 所有核心操作可通过键盘完成；
- Space：播放/暂停；方向键：调整 BPM；T：Tap Tempo；
- 输入框具有可见标签和错误说明；
- 当前拍使用 `aria-live` 时必须限频，避免每拍都造成屏幕阅读器噪声；
- 焦点样式清晰可见；
- 颜色满足正常文本对比要求；
- 动画遵循减少动态效果设置；
- 支持能力检测后的 Screen Wake Lock，失败时静默降级并显示状态，不把它作为播放前提。

## 14. GitHub Actions 与部署

使用两个工作流：

### CI

在 pull request 和推送时执行：

1. 安装锁定依赖；
2. lint；
3. TypeScript 类型检查；
4. 单元测试；
5. production build。

### Deploy

默认分支 CI 通过后：

1. 构建 Vite `dist`；
2. 按仓库名配置 GitHub Pages `base`；
3. 上传 Pages artifact；
4. 部署至 `github-pages` environment；
5. 使用 concurrency 防止多个正式部署互相覆盖；
6. 支持手动触发。

V1 使用客户端单页结构，但应避免依赖服务器 rewrite 的深层路由；核心页面保持在入口路径内，确保 GitHub Pages 刷新可用。

## 15. 测试策略

### 单元测试

- 拍号和重音默认值；
- 各细分的拍点生成；
- BPM 到时间间隔的换算；
- Tap Tempo 异常值过滤；
- 递增、递减、钳制目标和往返循环；
- Quiet Count 小节边界；
- 预设校验和迁移。

### 音频引擎测试

- 使用可注入的时间源和 AudioContext 适配器验证排程数学；
- 验证暂停、停止和重启不会创建重复节点；
- 验证播放中改速只影响允许调整的未来拍点；
- 真实浏览器测试只验证集成行为，不把听觉结果完全交给 CI 判断。

### 端到端测试

- 手机与桌面布局；
- 标准播放流程；
- Tap Tempo；
- 修改拍号和逐拍重音；
- 训练器完整循环；
- 预设保存、刷新恢复、导入导出；
- 专注模式；
- 不支持 Wake Lock 时的降级。

### 人工验证

- Chrome、Edge、Android Chrome、iOS Safari；
- 低、中、高 BPM；
- 30 分钟连续前台播放；
- 外接蓝牙和有线音频的基本行为；
- 页面隐藏、系统挂起和音频设备变化后的恢复。

## 16. 验收标准

1. 360 px 宽度无横向滚动，核心播放按钮无需滚动即可触达。
2. 强、次强、弱和静音在视觉和听觉上可区分。
3. 发声时间只由 Web Audio 音频时钟排程。
4. 快速播放/暂停、改速或切换预设不会叠音。
5. 所有拍号下的重音数组长度始终等于分子。
6. BPM 递增、递减、保持、重启和反向循环符合配置。
7. Quiet Count 只在小节边界切换。
8. 30 分钟测试中不存在算法导致的累计漂移。
9. 刷新后能够恢复最近配置和有效预设。
10. 无后端情况下可以完成所有 V1 核心功能。
11. GitHub Actions 能从干净环境完成检查、构建和 Pages 部署。
12. 页面进入后台时安全暂停，返回后不会自动产生突发点击声。

## 17. 实施前置条件

用户复核本规格后，下一步只生成详细实施计划。实施计划应明确：

- 每个阶段涉及的具体文件；
- 每个行为先写哪些测试；
- 每个提交的边界；
- GitHub Pages 仓库路径/base 配置；
- 最终部署前的浏览器人工验证清单。

在规格与实施计划均确认前，不开始应用代码实现。
